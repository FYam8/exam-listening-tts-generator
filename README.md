# Listening Step Trainer — Authorized Public / Noindex Build

2019〜2026年度のリスニング学習データを、利用者がファイル選択しなくても自動読み込みするWebアプリです。

## 検索抑制

この公開版では以下を実施しています。

- HTMLに `noindex,nofollow,noarchive,nosnippet,noimageindex`
- Googlebot / Bingbot向けnoindex
- `robots.txt` ではページ本体をクロール可能にしてnoindexを読ませ、埋め込み学習データのJSファイルのみクロール拒否
- 公式データを平文JSONとして置かず、Base64化した埋め込みデータとして配信
- sitemapを作成しない
- 公開ソースのタイトル・README・変数名には学校固有名を入れない

`noindex` は検索エンジンへの指示であり、アクセス制御ではありません。公開URLを知っている人は閲覧できます。

## 学習データ

ページを開くと2019〜2026年度のデータを自動読み込みします。通常、利用者がデータファイルを選択する必要はありません。

学習は2023年度から始めます。最近の傾向に近い問題で弱点を診断し、2019〜2022年度で補強したうえで、2024年度を中間確認、2025・2026年度を仕上げの模試に使う設計です。

- 6割ライン: 12/20
- 安定目標: 14/20
- 「今日やること」に、毎日1つ進めた場合の残り想定日数を表示

## 読み上げ音声

- Man欄には端末内の男性候補、Woman欄には女性候補だけを表示
- Narratorは別に選択可能
- 音声名から性別を判定できない端末では、その旨を画面に表示
- 音声の種類・品質はブラウザとOSにより異なる

### GitHub Pagesとrobots.txtの注意

`web/robots.txt` はページ本体を許可し、encoded content assetだけを拒否します。`Disallow: /` にはしません。

ただし `https://USER.github.io/REPO/` 形式のGitHub Pages project siteでは、project配下の `robots.txt` はオリジン直下 `/robots.txt` ではありません。したがって、検索抑制の主手段は `index.html` のnoindex metaです。noindex/robotsはアクセス制御ではありません。


検索で見つかりにくくしたい場合は、GitHubリポジトリ名にも学校名・学校略称・固有のプロジェクト名を入れず、外部サイトからリンクしないことを推奨します。

## v11: 3段階の類題設計

過去問で失点した後の補強を、短い類題だけで終わらせない構成に変更しています。

### Level 1 — 弱点ミニ練習
技能そのものを短く切り出して確認します。

- NEXT / REASON / NOT などの基礎確認
- CHANGE / TIME / MONEY の基本処理
- 3問 → 必要なら追加2問
- 短い問題を解けただけでは、本番相当の克服とは判定しません

### Level 2 — 本番相当の短会話
大問1のB系弱点、特に CHANGE / TIME / MONEY で使用します。

- 約60〜150語
- 5〜10ターン程度
- 情報更新・不要情報・計算・ひっかけを含む
- 即時確認は原則2問
- 2〜4日後の定着確認も本番相当の未見短会話を使用

### Level 3 — 本番相当の長い話
大問2で失点した場合に使用します。

- 160〜260語程度
- 1つの長い話＋2問
- PURPOSE / MAIN / DETAIL / TRUEFALSE / TIME / PLACE / REASON / NOT などを組み合わせる
- 2〜4日後も未見の長文セットで定着確認

### 元過去問とのマッチング
本番相当類題の選択では、元の失点問題に対して次を比較します。

- 技能タグ
- 文章量
- 会話ターン数
- 情報更新回数
- 不要情報・選択肢デコイの近似数
- 計算の有無
- 設問タイプ
- ひっかけ構造
- 語彙負荷の近似値

大問2は元問題のタグ組み合わせも考慮し、2019〜2026年度で現れる主要な設問ペアを1つの本番相当セットで確認できるようにしています。

### 定着判定
- A系の単純技能: 未見ミニ類題
- B系 CHANGE / TIME / MONEY: 未見の本番相当短会話
- 大問2: 未見の本番相当長文セット
- 最終的な転移確認: 次の未見過去問

本番相当類題に失敗した場合は、短い類題だけを繰り返して「克服」とはせず、スクリプトまたは弱点ミニ練習へ戻します。

## v12: ミス原因診断

過去問で間違えたとき、技能タグだけでなく「なぜ間違えたか」を補助診断として使います。ただし、ミス原因だけでLevel 2/3を省略・追加することはありません。進級判断の主軸は初回結果・再診断結果・A/B/C・問題タイプです。

### 自動診断
- 初回× → 再診断○: `ONE_PASS` 不安定
- 初回× → 再診断×: persistent miss

### ミス原因
スクリプト確認後に1つだけ選択でき、後から変更できます。

- HEAR
- VOCAB
- MEANING
- UPDATE
- CALC
- QUESTION
- MEMO
- CARELESS
- UNKNOWN

再診断でも不正解だった問題は、次へ進む前に1つ選択します。原因が判断できない場合はUNKNOWNを使います。初回×→再診断○の場合は原因入力は任意です。

### 原因別補強
- HEAR: 0.85倍から根拠文を聞き直す
- UPDATE: 情報更新語を自動強調
- CALC: TIME/MONEY系のLevel 1を優先
- QUESTION / MEMO / VOCAB / MEANING / CARELESS / UNKNOWN: スクリプト画面とLevel 1で重点指示を表示

原因は補強内容を変えますが、Level 2/3へ進む必要性そのものは変更しません。

### 反復原因
同じ原因が異なる過去問音声で2回以上出た場合にだけ、根本弱点候補としてダッシュボードへ表示します。

- A問題で反復: 最優先
- B問題で反復: 重点
- C問題だけ: 優先表示しない

同じ長文の2設問で同じ原因を選んでも、反復原因として二重カウントしません。

## v12.2: 再診断の選択肢表示

再診断では、音声を再生する前から回答選択肢を表示し、再生中も選択肢を表示したままにします。正解は「再回答を確定」するまで表示しません。再生中は選択肢を押せますが、確定操作は音声終了後まで無効にします。

`rediagnosis_ui_test.js` により、選択肢4つ/設問の描画、音声開始前のUI検査、正解非表示、再生中の確定防止を回帰検査します。採点・ONE-PASS・persistent miss・ミス原因・Level 1/2/3・年度ロードマップは変更していません。

## v13: A60 / B70 / C75 学習目標

数学アプリと同じ考え方で、英語の学習目標を A=60点 / B=70点 / C=75点 から選べます。これは学校公式の最低点ではなく、受験戦略上の学習目標です。

- A 60点: A問題を必須補強
- B 70点: A・B問題を必須補強
- C 75点: A・B・C問題を必須補強

目標変更時も初回得点・初回誤答履歴は書き換えません。必須補強対象、弱点集計、反復ミス原因、定着確認対象、年度ごとの残り補強数を再計算します。

同じ音声にA問題とB問題が混在する場合でも、A目標でAだけを終えた時点ではBを「完了済み」にしません。後からB=70点へ上げると、未補強のB問題が再び必須対象になります。

リスニング20点を60/70/75点へ比例換算する機能ではありません。

## v14: どこからでも正確に続きへ戻る

「後で続ける」「ダッシュボード」「ページ再読み込み」などで学習途中から離れても、`今日の学習を始める` は保存済みの**次にやる処理**を最優先で復元します。

保存対象:
- 過去問本番中の年度・Number・回答・再生済み状態
- 再診断の現在問題・回答・再生済み状態
- 再診断を確定済みなら「同じ問題の再回答」ではなくスクリプト練習へ
- Level 1 の選ばれた類題ID・現在位置・回答・再生済み状態
- Level 1 を回答確定済みなら次の類題または結果確認へ
- Level 2/3 の選ばれた類題ID・現在位置・回答・再生済み状態
- Level 2/3 を回答確定済みなら次セットまたは結果確認へ
- 定着確認の途中状態。失点確定後は同じ問題を再回答せず3問類題へ

保存データには問題本文・スクリプト・選択肢そのものを複製せず、問題ID・回答・進行位置だけを保持します。

progress schema は v6。従来のLocalStorageキーは変更していません。

## v15: 今日の学習ボタンを必ず次の実作業へ

`今日の学習を始める` は、画面表示時に保存した古いtaskではなく、クリックした瞬間の保存状態から `computeNextTask()` を再計算します。

回答確定済みの途中状態を消化した結果、内部的にいったんダッシュボードへ戻った場合も、その1クリックの中で次のtaskを再計算し、実際の次の問題・スクリプト・類題画面が開くまで自動で進めます。

例:
- 再診断確定済み → スクリプト練習
- Level 1回答確定済み → 次の類題 / 結果処理 → 必要ならLevel 2/3または次の再診断問題
- Level 2/3回答確定済み → 次セット / 結果処理 → 必要なら次の再診断問題
- 壊れた古い途中checkpoint → 同じクリック内で破棄し、次の有効taskを再計算

途中保存がある場合、ボタン表示は `続きから次へ進む` になります。

また、ユーザー向けの曖昧な `判定へ` 表示を廃止し、`結果を確認して次へ` に変更しました。ここで行うのは「合否判定」ではなく、そのミニ練習/本番相当類題の結果に応じて次の学習段階を決める処理です。

## v16: スクリプト画面の再固定を解消

v15では `今日の学習を始める` の再計算自体は正しくなりましたが、`activeSession.type === "script"` を「まだスクリプト画面を続けるべき」と固定していたため、一度スクリプト画面を開いた後にダッシュボードへ戻ると、Todayボタンが同じスクリプト画面を再表示し続けるケースが残っていました。

v16では、スクリプト画面を一度開いた `script` checkpoint は「スクリプト確認済み」と扱います。

- 再診断確定直後の `script-ready` → スクリプト画面を1回表示
- その後ダッシュボードへ戻り Today → 必須のミス原因入力がなければ Level 1 オリジナル類題へ直接進む
- 再診断でも不正解でミス原因未選択 → スクリプト/ミス原因画面を再表示し、原因選択を求める
- 原因選択後の Today → オリジナル類題へ進む

スクリプト画面下部のボタンも `スクリプト確認完了 → オリジナル類題へ` に変更しました。

## v17: 本番画面の選択肢消失を防止

本番画面で「再生中…」になるのに、年度・Number・回答選択肢が空白になる症状を修正しました。

原因候補は、UI変更やGitHub Pagesの更新時に、装飾用DOM（タイトル・進捗・ラベル）と `app.js` の期待が一時的に食い違うと、`renderExam()` が選択肢描画より前に例外停止する構造でした。さらに、公開更新時に古いJSがブラウザキャッシュに残ると、新旧HTML/JSの組み合わせが起こり得ます。

v17では:
- 回答選択肢をタイトル等より先に描画
- タイトル/進捗/ラベルは欠けても回答描画を止めない
- 音声開始前に回答選択肢がDOMにあることを検査
- 選択肢が復元できない場合は音声を開始しない
- 公開CSS/JSへ `?v=17` を付け、GitHub Pages更新後の古いアセット混在を回避

過去問の回答・採点・A/B/C・再診断・類題ロジックは変更していません。
